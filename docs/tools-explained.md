# GTM · GA4 · Looker Studio — 각 도구가 무엇을 하는가

세 도구를 처음 접할 때 생기는 오해를 바로잡고, 기능별로 "무엇을 하는 것인지 / 실무에서 언제 쓰는지"를 정리한 메모.

## 먼저 바로잡을 오해

- **GTM은 데이터를 저장하지 않는다.** 로그도, 이력도 GTM 안에는 없다. GTM은 교환기(스위치보드)다. 사이트에서 신호가 오면 "이건 GA4로, 이건 광고 플랫폼으로" 넘겨주기만 하고, 넘긴 뒤엔 아무것도 남기지 않는다. 데이터가 쌓이는 곳은 GA4(와 BigQuery)다.
- GTM 미리보기 화면에 이벤트가 순서대로 쌓이는 모습은 내 브라우저 한 대의 실시간 흐름을 잠깐 보여주는 것이고, 창을 닫으면 사라진다.
- GA4는 "실시간 현황판 + 집계"가 맞지만, 탐색 분석·잠재고객·다른 구글 도구와의 연결까지 포함해 생각보다 넓다.

## GTM — 교환기. "무엇을, 언제, 어디로 보낼지"를 정하는 곳

| 기능 | 뭐 하는 건가 | 실무에서 언제 쓰나 |
|---|---|---|
| 태그 | "보내라"는 명령. GA4 이벤트, 광고 전환 픽셀, 채팅 위젯 등 | 새 광고 플랫폼 붙일 때 사이트 코드 수정 없이 태그만 추가 |
| 트리거 | 태그가 실행될 조건. "이 이벤트가 오면", "이 URL이면", "이 버튼을 클릭하면" | "결제 완료 페이지에서만 전환 태그 실행" 같은 조건 |
| 변수 | 값을 꺼내는 통로. dataLayer 값, URL 일부, 클릭한 요소의 글자 등 | 상품 id·가격·회원 등급 같은 걸 태그에 실어 보낼 때 |
| 미리보기 | 게시 전 검사. 어떤 이벤트에 어떤 태그가 실행됐는지 보여줌 | 태그 하나 바꿀 때마다 확인 (QA) |
| 버전·게시 | 변경 묶음을 버전으로 저장하고 실제 적용. 이전 버전으로 되돌리기 가능 | 잘못 게시했을 때 1분 안에 롤백 |
| 작업공간 | 여러 사람이 동시에 다른 작업을 하는 임시 공간 | 담당자 A는 광고 태그, B는 GA4 태그를 따로 작업 |
| 가져오기/내보내기 | 설정 전체를 JSON으로 | 다른 사이트에 같은 설정 복제, 백업 (`gtm/container.json`) |
| 동의 모드 | 쿠키 동의 여부에 따라 태그 실행을 제어 | EU 트래픽, 개인정보 규정 대응 |
| 커뮤니티 템플릿 | 남이 만든 태그 종류를 가져다 씀 | 국내 광고 플랫폼(카카오·네이버) 태그 |

한 줄 요약: GTM은 "측정 설정을 코드 밖으로 꺼낸 것"이다. 사이트 배포 없이 측정을 바꿀 수 있게 해주는 게 존재 이유다. 분석팀이 GTM 권한을 갖고 있으면 개발팀 일정과 상관없이 태그를 고칠 수 있다.

## GA4 — 데이터가 쌓이고, 집계되고, 보이는 곳

| 영역 | 기능 | 뭐 하는 건가 | 실무에서 언제 쓰나 |
|---|---|---|---|
| 실시간 | 실시간 개요 | 최근 30분 | 태그 잘 붙었나 확인, 캠페인 시작 직후 유입 확인 |
| | DebugView | 내 브라우저 한 대의 이벤트를 파라미터까지 상세히 | 태그 QA 할 때 (미리보기의 GA4 쪽 짝) |
| 보고서 (미리 만들어진 것) | 획득 | 어디서 왔나: 채널·소스·캠페인별 사용자 | 광고 효율 주간 리포트 |
| | 참여도 | 무엇을 했나: 이벤트, 페이지, 체류시간 | 콘텐츠 성과, 페이지별 이탈 |
| | 수익 창출 / 리드 | 얼마나 샀나·신청했나 | 전환 추적 |
| | 유지 | 다시 왔나 | 재방문·충성도 |
| | 사용자 속성·기술 | 누가 왔나: 지역·기기·연령 | 타겟 설정 근거 |
| 탐색 분석 (직접 조립) | 자유 형식 | 원하는 측정기준×측정항목 표·차트 | 보고서에 없는 조합 볼 때 |
| | 유입경로 탐색 | 퍼널 | 이탈 구간 찾기 |
| | 경로 탐색 | 사용자가 실제로 이동한 순서를 나무 모양으로 | "메인 다음에 어디로 가나" |
| | 세그먼트 중복 | 두 조건을 만족하는 사용자 교집합 | "모바일이면서 리드인 사용자" |
| | 동질 집단 | 같은 주에 온 사람들의 이후 행동 | 캠페인별 잔존율 비교 |
| | 사용자 개별화 | 한 사람의 이벤트 타임라인 | CS 문의 확인, 이상 행동 추적 |
| 관리 (설정) | 이벤트·주요 이벤트 | 어떤 이벤트를 전환으로 칠지 | `generate_lead`에 별표 |
| | 맞춤 정의 | 우리가 보낸 파라미터(`model_id` 등)를 보고서에 쓸 수 있게 등록 | 파라미터가 보고서에 안 보일 때 |
| | 잠재고객 | 조건으로 사용자 묶음 정의 | 광고 재타겟 목록으로 넘김 |
| | 데이터 필터·보관·동의 | 내부 트래픽 제외, 보관 기간 | 사무실 IP 제외 |
| 연결 | BigQuery / Google Ads / Search Console 링크 | 다른 구글 도구와 데이터 주고받기 | 광고비와 전환 붙이기, 원본 내보내기 |

한 줄 요약: GA4는 "이벤트 창고 + 집계 엔진 + 기본 화면"이다. 정해진 질문은 보고서로, 조금 다른 질문은 탐색 분석으로 답하고, 그것으로도 안 되는 질문은 BigQuery로 넘긴다.

## Looker Studio — 여러 데이터를 한 장에 모아 남에게 보여주는 곳

Looker Studio는 데이터를 저장하지도 계산하지도 않고, 다른 곳의 데이터를 읽어서 그린다. 그래서 기능이 "데이터 연결", "그리기", "공유" 세 묶음이다.

| 묶음 | 기능 | 뭐 하는 건가 |
|---|---|---|
| 데이터 소스 | 커넥터 | GA4, BigQuery, 구글 시트, Google Ads, 검색 콘솔 등에 연결. 카카오·네이버 광고는 시트를 거치거나 유료 커넥터 |
| | 필드 | 연결한 데이터의 열 목록. 이름을 한글로 바꾸거나 형식을 지정 |
| | 계산된 필드 | 간단한 수식. 예: 리드 수 ÷ 광고비 = 리드당 비용 |
| | 데이터 혼합 | 두 소스를 공통 키로 붙임. 예: GA4 리드 + 시트의 광고비 |
| 보고서 | 페이지 | 대시보드 한 장 = 페이지. "요약 / 채널 / 퍼널" 식으로 나눔 |
| | 차트 | 시계열, 막대, 표, 스코어카드(큰 숫자 하나), 지도, 퍼널 등 |
| | 컨트롤 | 보는 사람이 직접 조작하는 필터. 기간 선택, 채널 드롭다운 |
| | 테마·레이아웃 | 브랜드 색, 로고, 설명 문장 |
| 공유 | 링크·권한 | 구글 문서처럼 보기/편집 권한 |
| | 예약 전송 | 매주 월요일 아침 PDF로 메일 발송 |
| | 임베드 | 사내 포털에 삽입 |

실무에서 쓰는 모습: 대행사 분석팀이 클라이언트에게 주는 "월간 성과 대시보드"가 전형이다. 1페이지 요약(방문·리드·비용·리드당 비용 스코어카드), 2페이지 채널별 성과, 3페이지 퍼널, 4페이지 캠페인 상세. 데이터는 GA4 커넥터로 직접 붙이거나, 무거운 계산은 BigQuery에서 미리 표로 만들어두고 그 표를 연결한다. 클라이언트는 링크만 열면 되고 GA4 권한은 필요 없다.

이 프로젝트에 적용하면: BigQuery에서 `sql/03_channel_attribution.sql` 결과(채널별 리드→시승→계약)를 표로 저장하고, Looker Studio에서 그 표를 연결해 "채널별 계약 기여도" 막대 차트 + GA4 커넥터로 "일별 방문·리드" 시계열 + 퍼널 페이지를 만들면 세 도구가 한 화면에 모인다.

## 세 도구를 한 문장씩

- **GTM**: 저장 안 함. "무엇을 언제 어디로 보낼지"의 규칙만 관리하는 교환기
- **GA4**: 이벤트를 저장·집계하고, 정해진 보고서와 조립형 탐색 분석으로 보여주는 곳
- **Looker Studio**: 저장·계산 안 함. 여러 곳의 데이터를 읽어서 한 장에 그려 공유하는 곳

```
사이트 ──dataLayer──▶ GTM(교환기) ──▶ GA4(저장·집계·기본 화면) ──▶ BigQuery(원본·SQL 계산)
                                                   └────────────────────┴──▶ Looker Studio(그려서 공유)
```
