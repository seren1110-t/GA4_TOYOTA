# GA4 × GTM 설치 과정 — 처음부터 순서대로

GA4·GTM을 한 번도 안 써본 사람이 이 저장소를 그대로 따라 할 수 있게, 설계부터 데이터 확인까지 순서대로 적은 기록. 각 단계는 "왜 필요한가 → 무엇을 했나 → 어디서 눌렀나 → 걸린 함정" 순서다.

## 0. 설계: 무엇을 잴지 먼저 정한다 (측정 기획서)

**왜** — 태그를 먼저 붙이면 나중에 "이 숫자가 뭐였지?"가 된다. 질문을 먼저 정하고, 질문에 답하려면 어떤 행동을 세야 하는지 표로 만든다.

**무엇을** — `docs/measurement-plan.md`
- 퍼널 5단계: 방문 → 라인업 → 모델 상세 → 폼 시작 → 시승 신청 완료
- 이벤트 이름과 파라미터 (예: `view_item` + 모델 id/이름/가격, `generate_lead` + 리드 id/지역/첫 유입 채널)
- 고객 ID 규칙: 전화번호 해시 → 웹과 딜러 데이터의 공통 키
- UTM 규칙: 광고 링크 뒤에 붙일 `utm_source / medium / campaign` 값 표준

**함정** — GA4가 자동으로 세는 이벤트(`page_view`, `scroll`, `form_start`)와 직접 심는 이벤트가 겹칠 수 있다. 어느 쪽을 기준으로 삼을지 여기서 정해둔다.

## 1. 사이트에 "메모판"(dataLayer)만 심는다

**왜** — 사이트 코드가 GA4를 직접 호출하면, 측정 항목을 바꿀 때마다 개발자가 코드를 고쳐야 한다. 사이트는 "무슨 일이 있었다"만 적고, 어디로 보낼지는 GTM이 결정하게 분리한다.

**무엇을** — `site/assets/app.js`
```js
window.dataLayer = window.dataLayer || [];
dataLayer.push({ event: 'view_item', ecommerce: { items: [{ item_id: 'ravon', price: 41500000 }] } });
```
- 페이지가 열리면 `view_item_list` / `view_item`, 버튼을 누르면 `cta_click`, 폼 제출 후 완료 페이지에서 `generate_lead`
- 시승 신청 시 고객 ID를 만들어 `dataLayer.push({ user_id: 'C…' })` — 이후 모든 이벤트에 이 사람 표시가 붙는다

**어디서** — 코드 안. 화면 작업 없음. 오른쪽 아래 검은 패널은 dataLayer에 쌓이는 걸 눈으로 보려고 연습용으로 붙인 것.

## 2. GA4 속성 만들기 (데이터를 받을 그릇)

**왜** — 이벤트가 도착할 목적지가 있어야 한다. GA4는 계정 → 속성 → 데이터 스트림 3층이다.

**어디서** — analytics.google.com → 측정 시작
1. 계정 이름 `TOYOMO Practice`
2. 속성 이름 `TOYOMO 웹사이트`, 시간대 대한민국, 통화 KRW
3. 업종·규모(통계용), 비즈니스 목표 "리드 생성"(기본 보고서 구성이 리드 중심으로 바뀜)
4. 서비스 약관 동의 (계정 주인이 직접)
5. 플랫폼 "웹" → 스트림 URL·이름 입력 → **측정 ID `G-G6Q8S0SC89`** 확보

**함정** — 측정 ID의 O/0 같은 글자를 눈으로 옮기면 틀린다. 화면에서 복사하거나 코드로 읽는다.

## 3. GTM 컨테이너 만들기 (태그를 담는 상자)

**왜** — 사이트에는 GTM 스크립트 한 줄만 넣고, "무엇을 언제 GA4로 보낼지"는 GTM 화면에서 바꾼다. 마케터가 개발 없이 태그를 관리하는 구조.

**어디서** — tagmanager.google.com → 계정 만들기
- 계정 `TOYOMO Practice`, 컨테이너 `toyomo-web`, 플랫폼 웹 → 약관 동의 → **컨테이너 ID `GTM-54K728DZ`**
- 사이트 쪽: `site/assets/config.js`의 `GTM_ID`에 이 값을 넣으면 `app.js`가 GTM 스크립트를 불러온다

## 4. GTM 안에서 부품 조립 (변수 · 트리거 · 태그)

**왜** — dataLayer의 메모를 GA4 이벤트로 번역하는 규칙이 필요하다.

| 부품 | 뜻 | 우리 것 |
|---|---|---|
| 변수 | dataLayer에서 값을 꺼내는 통로 | `DL - model_id`, `DL - user_id` … 21개 |
| 트리거 | "언제" 실행할지 조건 | `CE - Ecommerce events` (view_item_list/select_item/view_item), `CE - Site interaction events`, `CE - generate_lead` |
| 태그 | "무엇을" 실행할지 | `GA4 - Google 태그 (config)`: 모든 페이지에서 GA4 로드 + user_id 설정 / 이벤트 태그 3개: 이벤트 이름·파라미터를 GA4로 전송 |

**어디서** — 손으로 28개를 만드는 대신 `gtm/container.json`을 관리자 → 컨테이너 가져오기 → 병합. 미리보기 화면에 "28개 추가됨"이 뜨면 성공.

**함정** — 파라미터 이름이 겹치면 값이 섞인다 (예: 폼 선택값과 금액이 둘 다 `value`) → `field_value`로 분리했다.

## 5. 미리보기로 검사 (Tag Assistant)

**왜** — 게시 전에 "어떤 이벤트에 어떤 태그가 실행됐는지"를 본다.

**어디서** — GTM 작업공간 → 미리보기 → 사이트 URL 입력 → 연결. 왼쪽에 이벤트가 순서대로 쌓이고, 각 이벤트를 누르면 실행된 태그/안 된 태그가 나뉜다.

**함정** — Tag Assistant는 자기가 연 창만 감시하고, 연결이 자주 끊긴다. 안 잡히면 재연결하거나 실시간 보고서로 검증한다.

## 6. 게시 (버전 만들기)

**왜** — 작업공간의 변경은 게시 전까지 실제 방문자에게 적용되지 않는다.

**어디서** — 제출 → 버전 이름(`v1 - GA4 config + funnel events`) → 게시. 버전 목록에 "실시간, 최신"이 붙는다.

**함정** — 게시 직후 브라우저가 옛 `gtm.js`를 캐시에서 쓴다. 강력 새로고침(Ctrl+Shift+R)으로 확인한다. "게시했는데 안 나와요"의 1순위 원인.

## 7. GA4 실시간으로 도착 확인

**왜** — 게시 후 1분 안에 데이터가 GA4에 들어오는지 보는 가장 빠른 화면.

**어디서** — GA4 보고서 → 실시간 개요. 활성 사용자 수, 페이지 제목, 이벤트 이름 카드(다음 페이지 화살표로 전체 목록)를 본다. `generate_lead` 8건이 스크립트의 리드 8건과 일치하면 수집 정상.

## 8. 배포하고 데이터 쌓기

- GitHub Pages로 `site/`를 공개 URL에 올림 (`.github/workflows/pages.yml`). Public 저장소여야 무료.
- `scripts/simulate.py`가 가상 방문자 40명을 광고 채널별로 보내 퍼널을 각기 다른 깊이까지 진행시킨다. GA4는 진짜 사용자로 인식한다.
- `scripts/gen_offline.py`가 리드에서 딜러 시승·계약 CSV를 만든다 (같은 고객 ID 규칙).

## 9. GA4 탐색 분석으로 퍼널 그리기

**어디서** — 탐색 분석 → 유입경로 탐색 → 단계 연필 → 각 단계 이름과 이벤트를 우리 5개로 교체 → 적용.

**읽는 법** — 단계별 사용자 수와 "이전 단계 대비 이탈률". 가장 큰 이탈 구간이 개선 실험 지점.

**함정** — 실시간에는 보이는 이벤트가 탐색 분석에는 24~48시간 늦게 나타날 수 있다. "이벤트 누락"으로 오판하지 않는다.

## 10. BigQuery로 넘기기

**왜** — GA4 화면은 정해진 질문만 답한다. "유튜브 광고 → 시승 → 계약"처럼 딜러 데이터와 붙이는 질문은 원본 이벤트를 SQL로 계산해야 한다.

**어디서**
1. 구글 클라우드 프로젝트 `toyomo-ga4` 생성 (샌드박스, 결제 없음)
2. GA4 관리 → 제품 링크 → BigQuery 링크 → 프로젝트 선택 → 매일 내보내기 → 제출. 연결 **다음날부터** `analytics_556171914.events_YYYYMMDD` 표가 생긴다
3. 딜러 데이터는 `sql/00_load_crm.sql`(CSV를 SQL로 변환한 파일)을 BigQuery 편집기에서 실행 → `crm` 데이터세트에 표 3개
4. `sql/01~04`: 웹 퍼널 → 고객 여정 조인 → 채널 기여도 → BigQuery ML 리드 스코어링

